# Incident timelines and primary-group diagnosis

New analyses parse plain text, Compose-prefixed logs, and JSON lines into events before ranking source files. Events retain original line ranges, observed services, timestamps, request/trace identifiers, stack frames, and explicit exception-chain relationships. The Logs & trace view displays every group and links back to original input. Its timeline is separate from the workflow's execution-stage timings.

JSON records accept `message`/`msg`, `timestamp`/`@timestamp`/`time`, `service`/`service_name`/`service.name` (including nested `service.name`), `trace_id`/`traceId`, and `request_id`/`requestId`. The first valid alias wins. Structured fields override message metadata; conflicts are reported. Escaped multiline messages are parsed as one record. Malformed JSON remains text with a limitation.

Trace IDs associate events across services. Request IDs also associate events when they do not bridge different trace IDs. A request ID observed with multiple traces cannot attach request-only events to either trace. Without identifiers, independent errors remain separate even when timestamps or services match. Ambiguous unprefixed continuation lines retain unknown ownership. Explicit Python, Java `Caused by:`, and Node `[cause]:` chains remain distinct from event ordering.

Exactly one group supplies diagnosis evidence. Error-bearing groups are preferred; an observed service matching the existing service hint further narrows that selection. The highest file score wins, with original input order breaking ties. If scores are zero, the earliest eligible group wins. The report records the selection reason and any unmatched hint. Hints never create observed service ownership. Other groups remain inspectable context and do not contribute to ranking or hypothesis prompts.

Source order is the default. Chronological display is available only when every event in the group has a comparable timestamp with explicit date and timezone. No timezone is guessed and no clock-skew correction is attempted. Shared IDs and chronology establish association, not causation.

JSON reports include `incident_context` version 1. Markdown contains group summaries and primary-group events. Candidates expose `group_id` and matching `event_ids`. Iterative investigation receives citable primary events and exception chains, subject to the existing evidence and prompt limits; omissions and clipping are reported. Historical reports and saved investigation checkpoints without timeline fields retain their original behavior.

Legacy Temporal activities keep immutable parsed snapshots in the shared control store's existing JSON storage. Correlation and diagnosis activity results carry `incident_context_ref` instead of expanded context. Internal consumers can resolve that reference with `incident_copilot.workflows.log_context.hydrate_parsed_log({"incident_context_ref": reference})`; the result includes `incident_context` and the original parsed input. Missing or mismatched snapshots fail explicitly. API, CLI, and dashboard reports contain the expanded context. Back up the control store with incident artifacts to retain referenced snapshots.
